# Screenshot Tests

This package contains Playwright-based screenshot tests for desktop surfaces.

## IMPORTANT: Writing Screenshot Content

**All screenshot test content MUST be consistent with
[`UNIVERSE.md`](./admin/environment/demo_space/UNIVERSE.md).** This applies to every piece of
content in every screenshot test: character names, roles, projects, dates, message content, document
titles, task names — everything. Before writing or modifying any screenshot test content, read
`UNIVERSE.md` in full. Inconsistencies undermine the coherence of the screenshots and make them
unusable as marketing or support materials.

## Workflow

1. Generate or refresh screenshots on Linux:
    - `bazel run //app/screenshot_tests:${name}`
    - Examples:
        - `bazel run //app/screenshot_tests:documents`
        - `bazel run //app/screenshot_tests:tasks`
        - `bazel run //app/screenshot_tests:chat`
        - ...

    Screenshots are written to `app/screenshot_tests/screenshots/${testName}` in the repo.

    Screenshot baselines are expected to be generated on Linux machines so they match the
    environment used by CI. If you are developing on macOS, do not regenerate screenshots locally
    (if you try, the command will throw). Wait for CI to run, then download the CI-generated
    screenshots into the repo with: `bazel run //app/screenshot_tests:sync`.

    You may also use `bazel run //app/screenshot_tests:${name}_preview` to preview screenshots in a
    temporary directory.

2. Validate screenshots on Linux:
    - `bazel test //app/screenshot_tests:${name}_screenshot_test`
    - Examples:
        - `bazel test //app/screenshot_tests:documents_screenshot_test`
        - `bazel test //app/screenshot_tests:tasks_screenshot_test`
        - `bazel test //app/screenshot_tests:chat_screenshot_test`
        - ...

3. Preview screenshots on any platform:
    - `bazel run //app/screenshot_tests:${name}_preview`
    - Examples:
        - `bazel run //app/screenshot_tests:documents_preview`
        - `bazel run //app/screenshot_tests:tasks_preview`
        - `bazel run //app/screenshot_tests:chat_preview`
        - ...

    Writes screenshots to a temporary directory. You can use this while developing on macOS to
    preview the screenshots before the final screenshots are generated by our Linux CI runners.

The tests compare images using `looks-same` and store diffs under `bazel-testlogs` when there is a
mismatch.

## Code style guide

- Only create on space per screenshot test file. Take all screenshots within the same space.
  `createDemoSpace()` takes a couple seconds to run so this is a meaningful performance
  optimization.

## Content style guide

- When writing content, vary the lengths of text. If all messages have about the same length (e.g.
  all messages are one and a half sentences or about 30 words) then the content won't look
  realistic. For example, some messages should be one word responses and others should be long
  rambling tirades. Vary content length in a way that feels natural.
